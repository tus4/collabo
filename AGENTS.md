# Teacher / COLLABO project instructions

## Repository scope

- GitHub work in this project is limited to `tus4/collabo` and `tus4/data1`.
- Do not access other repositories or import their code, data, settings, or work history.
- Keep local checkouts and branches separate from other projects. Explicitly identify owner/repository for GitHub operations.
- Verify the repository and its actual default branch when starting work. Verify the target repository and branch again before push, PR creation, or merge.
- Merge only when the user requests it. Report changes and validation separately for each repository.

## Web UI copy preference

- Do not add sentence-style explanatory copy, introductory slogans, or descriptive subtitles to web screens unless the user explicitly requests them.
- Use concise labels, values, units, and controls. Keep detailed methodology in project documentation.
- Preserve functional validation messages, errors, and accessibility instructions needed to use the interface.
- Keep the homepage free of the removed `RESEARCH PLATFORM` / data freshness header row and the Optimizer subtitle.

## Generated site

- `template/platform.html` and `template/platform/` are the source of the analysis homepage.
- Keep `docs/index.html` and `docs/platform/` synchronized so the live page and later data rebuilds retain the same UI and favicon.
- Do not modify market data for presentation-only changes.
